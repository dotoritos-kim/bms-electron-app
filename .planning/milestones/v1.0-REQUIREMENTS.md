# Requirements — Milestone v1.0: 파일 로딩 프리징 버그 수정

## Milestone v1.0 Requirements

### Performance: BMS 파싱 (메인 스레드 블로킹 제거)

- [x] **PERF-01**: 차분 파일 선택 시 UI가 즉시 반응함 (BMS 파싱이 메인 스레드를 블로킹하지 않음)
- [x] **PERF-02**: 홈 화면에서 파일 선택 즉시 제목/BPM/키모드가 표시됨 (Phase 1 빠른 결과)
- [x] **PERF-03**: 통계(노트 수, 스크래치 수 등)가 이후 업데이트됨 (Phase 2 결과)
- [x] **PERF-04**: 파일 선택 중 오류 발생 시 에러 상태가 표시됨 (Worker PARSE_ERROR 처리)

### Performance: 취소 메커니즘

- [x] **CANCEL-01**: 파일 A 로딩 중 파일 B를 선택하면 A 로딩이 즉시 취소됨
- [x] **CANCEL-02**: 빠른 연속 선택 시 마지막 선택 파일의 결과만 표시됨 (requestId guard)

### Performance: Editor 오디오 종료

- [x] **AUDIO-01**: Editor에서 홈으로 돌아갈 때 오디오 디코딩이 즉시 중단됨
- [x] **AUDIO-02**: Editor 이탈 후 백그라운드 CPU 사용률이 증가하지 않음
- [x] **AUDIO-03**: 새 파일로 Editor 진입 시 이전 오디오 리소스가 완전히 해제됨

### Performance: 파일 스캔

- [x] **SCAN-01**: 폴더 스캔 시 BMS 파일 stat 조회가 병렬로 실행됨 (batchSize=20)

### Testing: 회귀 방지

- [x] **TEST-01**: BMS Worker Phase1/Phase2 파싱 결과 정확성 테스트
- [x] **TEST-02**: requestId race condition 회귀 방지 테스트
- [x] **TEST-03**: Editor abort bail-out 테스트
- [x] **TEST-04**: AudioPreloader.abort() 동작 테스트
- [x] **TEST-05**: scanDir 병렬 stat 결과 동일성 테스트

## Future Requirements

- .bms.meta 파싱 결과 캐시 (두 번째 열기부터 즉시 로드)
- AudioContext 앱 수준 싱글턴 (Editor/Player 간 공유)
- Home 파일 목록 가상화 (100개 이상 파일 렌더링 최적화)

## Out of Scope

- .bms.meta 파싱 캐시 — CEO 리뷰에서 제외, 별도 마일스톤에서 구현
- AudioContext 싱글턴 — per-request 방식이 더 단순, 현재 불필요
- Home에서 Timing/Positioning Worker 직렬화 — Home은 stats/headers만 필요, 직렬화 복잡성 불필요
